## 产品与范围

面向本人和少量朋友的私人健身记录工具。当前以原生微信小程序验收为主，React 网页采用相同业务规则；继续使用 FastAPI、PostgreSQL、SQLModel、Alembic 和现有登录。视觉为白底、深色文字、绿色强调。

本轮包含默认每周安排、本周换日、本次动作调整、个人动作库、逐动作推进、次数和时长记录、独立休息、显式提交、科学总结、微信登录和照片日期日志。网页照片日志与保存后总结已接入，训练调整、独立动作库管理与更多菜单继续对齐；真实微信身份和手机体验仍需验证。正式发布准备在核心流程验收后推进；RAG/Agent、学习监督、社交和成长植物暂不进入本轮。

## 必须遵守的业务规则

- 周一至周日，每一天最多一个计划安排，一周最多七个；每个安排可以包含多个动作。修改占用星期时展示双方变化并确认交换。旧灵活及异常超限计划完整保留，由用户修正并确认星期。
- 开始计划训练保存计划身份、训练日、来源星期、原始目标和本次目标；计划改动不影响进行中草稿和历史。
- 本次全部非空目标组达标才完成安排。不同记录的部分组不合并；仅打卡、额外组和临时训练不顶替计划目标。重复完成同安排，本周只计一次。
- 实际训练次数按保存记录与真实日期统计，和完成安排数分开。继续草稿、重试保存、历史修改均不新增次数；跨周不自动补上周。
- 替换只转移未达标目标，保留已做组；删录入行或移除动作不降低目标。降低目标和加入额外动作到目标清单均需明确确认，空目标清单不能完成计划。
- 我的动作包含自建和收藏。动作库有稳定身份，计划和训练保存独立快照；改库名称、备注或删库动作不改已有计划和历史。
- 次数组要有效次数并确认完成，自重重量可留空；时长组要正整数实际秒数并确认，有目标秒数时需达到目标。
- 总计时独立于组间休息。后台或锁屏继续按时间戳计算；稍后继续暂停并保留。总结冻结用时并结束休息，返回训练恢复累计计时并清除本次校正；历史编辑和补录不自动计时。
- 流程为沿用计划 → 逐动作记录 → 动作完成回顾并推进 → 提交训练 → 已保存总结 → 可选照片、感受和备注。最后一个动作完成后冻结用时、等待明确提交；继续待提交草稿保持冻结。部分训练可以保存。失败保留内容和请求身份，重试不新增记录。
- 快照版本 3，继续通过 `/api/v1/fitness/state` 原子读取/保存；私人库放在用户资料 JSON。未确认的旧请求先原样核对回执，再提交升级后内容。旧客户端不得覆盖新版字段。
- 本周日期覆盖不修改长期模板；恢复默认安排不能重新分配已有训练或草稿的日期。调整今天先暂停计时，点击开始后再计时。
- 训练保存与照片上传独立；照片按真实训练日期归档，删除训练保留照片并解除关联。系统选图或切后台不丢上传队列，账号变化不得写入新账号。
- 小程序主登录为微信登录；已有网站账号先验证再绑定。AppSecret 只在服务端；重新微信登录不能自动切换到另一内部账号。
- 账号隔离、版本冲突和幂等保存必须保留。图表只展示实际数据；持平和休息保持中性，不推断训练质量、肌肉恢复或动作安全。
