# 健身账号同步

页面 → `useFitnessData.ts` / `FitnessSync` → 生成的 `FitnessService` → `/api/v1/fitness/state` → `crud.py` → SQLModel / Alembic → PostgreSQL。

## 保存与恢复

GET 返回 `{revision, data}`，首次没有记录时 data 为 null。PUT 提交 `{expected_revision, mutation_id, data}`，成功返回新版本。

账号归属来自登录令牌，客户端不能指定 owner。管理员也只能访问自己的健身记录。计划、训练草稿、完成记录、个人动作库与收藏、目标、体重与保存回执在同一事务提交。草稿/历史保存当时的动作与组快照，修改计划不会改写旧训练。训练日最多 7 天，固定模式下星期不可重复。

输入立即缓存在本机，短暂延迟后同步；打卡、保存计划、删除等操作等待服务器确认后显示成功。重试保留已发送请求的 ID 与内容，服务端回执避免重复写入。两个页面基于相同版本保存时，后提交者得到 409，不覆盖前者；页面提供导出本机记录和备份后读取云端的操作。

断网后本机待同步内容保留，恢复网络或点击重试继续。localStorage 存储同步元数据与同一份完整快照，兼容早期独立记录键。退出/重新登录会重新读取账号，避免复用旧的查询结果。损坏的缓存不会自动覆盖。

体验页只有本机示例，不调用健身接口。旧超过 7 天的本机计划仍能读取，需用户编辑至 7 天以内才能提交；不截断记录。登录照片使用独立私有接口，详见 [照片存储](FITNESS_PHOTOS.md)。
