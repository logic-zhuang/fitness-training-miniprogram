# 健身记录 v2 实施规格

更新：2026-10-04。用户确认的规则已进入代码；具体自动检查、网页、开发者工具和真机结果分开记录于 [验收记录](../FITNESS_V2_ACCEPTANCE.md)。小程序优先，网页保持相同业务规则；沿用现有 Stitch 视觉，无需重做页面。

## 七日计划

周一至周日七行，空行为休息；没有训练日上移/下移。点一天编辑名称、动作、1–100 目标组数，时长动作另有可选每组目标秒数。星期列表显示占用；选择占用星期先展示双方变化、确认交换，取消保持原草稿。

返回周概览保留草稿并滚动到刚编辑的日；整份统一保存，有实际修改才提示未保存。保存失败保留输入。旧顺序或异常超限计划保留全部安排，逐项确认/修正后保存；不静默截断。修改计划只作用于以后开始的训练。

## 统一动作库

计划和训练采用同一选择逻辑：默认我的动作（自建＋收藏内置），另有内置和最近使用。最近从草稿和实际历史提取；可将旧自定义动作保存到个人库。名称搜索、部位筛选，每项显示名称、部位和记录方式，器械、备注可选。

多选添加，单选替换。创建填写名称、部位、次数/时长方式；相同名称、部位、方式提示使用已有动作。收藏使用内置身份，不复制。自建动作可以编辑；改库不改已有计划和历史。删除需确认，只移出个人库，旧快照保留。账号变化后旧选择器不能写到新账号。

## 训练与目标

开始计划训练，存计划身份、日身份、来源星期、原始目标和确认后的本次目标。每目标组有稳定 ID，实际组关联目标；同一目标不能有两个实际组。

次数需要正整数次数及完成确认，自重重量可留空；时长需要正整数秒数及完成确认，有目标秒数时实际值须达到目标。额外组只计实际数据，不补其他动作目标。各目标均达标且清单非空才完成。记录保存部分结果，同一安排两条部分记录不合并；至少一次完整清单才点亮计划。

菜单支持添加、替换、移到指定位置、移除实际动作、调整本次目标。替换只转移未达标目标：卧推 3 组已做 1 组，换推胸后保留卧推数据，新动作承担剩余 2 组，完成显示调整后完成。删录入行不减少目标，新增行先恢复缺失目标行，再计额外组。移除整个动作后仍保留目标，提供恢复缺失录入行入口；减少目标或将额外动作加入目标需明确确认。本次修改不回写每周模板。

## 计时与保存

流程：训练中 → 查看总结 → 确认保存 → 保存结果。总计时有暂停、继续和稍后继续；后台/锁屏不自动暂停，按时间戳恢复。稍后继续暂停并存草稿。组间休息为独立固定条，可展开、暂停/继续、增加时间、取消。时长动作支持手输实际秒数和当前组计时，确认完成后才开始休息。

总结冻结总计时并结束休息，展示日期、来源安排、用时、各动作实际组与数据、目标对照、感受和备注。未达标允许继续或保存部分训练。用时可手工校正；返回实时训练恢复累计用时并清除校正。补录与历史编辑不启动自动总计时，可填用时；未填未知。

失败保留内容、原训练 ID 和请求身份，不能因重试新增记录。已写入但回执丢失时原样重发；新修改等原请求核对后再以新版本保存。账号变化、冲突和断网不丢本机副本或误写其他账号。

## 统计与可视化

首页分别显示计划完成 X/Y 个安排与实际训练 N 次。按真实日期归周一至周日，同周同计划日最多完成一次，跨周不自动补上周。计划完成只用各记录自己的目标快照，之后模板变化不重算过去是否达标。仅打卡、临时和重复记录保留实际次数，不自动点亮其他安排。

七日状态：休息、待训练、部分完成、已完成、调整后完成；有记录而尚未达到任何目标时显示已记录/未达目标。历史展示来源星期与真实日期、实际组、代表数据、备注。部位分布以完成组数计算，网页趋势曲线和小程序轻量柱条均可打开原记录；次数同时可核对重量与次数，时长展示秒数。持平正常，不生成质量分、恢复判断或惩罚休息。

## 数据与迁移

继续 `/api/v1/fitness/state` 原子读取保存，快照版本 2；个人库与收藏在用户资料 JSON，动作和训练保持独立快照，新增 Alembic 迁移。后端校验类型、动作/组/目标身份和关联，并保留账号隔离、CAS 冲突及回执幂等。

旧缓存先备份后兼容读取。旧历史目标缺失标目标未保存，不推断达标；旧草稿继续前确认当前目标，或明确仅保留旧记录。旧计时只保留经过时间，无法推算过去暂停。待确认 v1 请求先保留原内容和 ID 核对回执，再迁移生成 v2 请求；未命中旧回执的 v1 写入返回 426，不能覆盖新版字段。

主要代码：网页 `src/features/fitness/{model,goals,library,insights,sync}.ts`，原生 `components/exercise-picker`、`pages/plan-edit`、`pages/workout`，后端 `models.py`/`crud.py`/`routes/fitness.py`。小程序业务模块和网页客户端都通过生成流程更新。

## 不进入本轮

成长植物、社交、Agent、人体正背面复杂热区图、质量评分、自动增重和视频动作判断。先让真实训练、正常休息和瓶颈期回顾都能用；研究依据保留在 [参考调研](FITNESS_REFERENCE_RESEARCH.md)，没有复制第三方代码或素材。
