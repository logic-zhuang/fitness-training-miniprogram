# Stitch 前端 UI 设计提示词

2026-10-04：本轮已根据现有设计实现 v2，用户无需重新制作整套页面。以下提示词同步为最新规则，供以后局部迭代参考；业务以 [v2 规格](FITNESS_NEXT_ITERATION.md) 为准。

## 第一轮：统一视觉与五个核心页面

```text
你是一位擅长移动端工具产品的资深 UI/UX 设计师。请为“训练手记”（暂定名）设计一套可用于开发的高保真界面。

产品背景：
这是本人和少量大学生朋友日常使用的私人健身记录工具，帮助用户安排每周训练、边练边记录动作、完成后打卡、回看历史和身体变化。后续会扩展个人健身知识库与 AI 助手，但本次先聚焦健身记录。

落地目标：
使用已有 FastAPI + React + TypeScript + Tailwind CSS 项目实现，先做手机优先的响应式网页，未来再适配微信小程序。不要设计成健身房宣传站或预约系统。

视觉方向：
白色内容面、浅灰页面底色、深色文字、克制的运动绿强调。整体清晰、轻量、现代、亲切，有运动感但不做健身海报。
基线色：主绿 #18784E，浅绿 #EAF5EE，背景 #F4F6F5，内容白 #FFFFFF，主文字 #17251D，次文字 #52645A，分隔线 #DCE5DF。
使用中文无衬线字体、统一线性图标、8px 间距体系、约 12px 圆角、16px 页面边距。正文约 16px，标题 22–24px。操作区域至少约 44px。
不要大面积渐变、重阴影、荧光色、巨幅肌肉人物、励志标语或密集管理表格。保持留白和信息层级，避免所有内容都做成同样的大卡片。

尺寸与导航：
以 390px 宽手机为主，考虑 320–430px 适配。底部四个入口：“训练 / 计划 / 记录 / 我的”。
训练进行中是独立页面，采用返回导航和底部主要操作，不保留占空间的底部四标签。
考虑底部安全区域、单手操作和数字键盘弹出状态。系统状态栏和微信胶囊只可作为外部预览框架，不是网页内容。
所有可见文案使用简体中文。数字明确带单位 kg、次、组、分钟。

请先生成以下五个核心页面，共用同一套组件、配色、字体和导航：

1. 训练首页
显示当前周、“计划完成 2 / 4 个安排”与“实际训练 3 次”，七天安排按周一至周日区分休息、待训练、部分完成、完成与调整后完成；突出今天安排或继续草稿。
本周列表：胸＋三头已完成、腿已完成、背＋二头待完成、肩＋腹待完成。
提供低强调的“临时训练”“快速打卡”“调整安排”入口。有草稿时主要按钮变为“继续训练”。

2. 计划详情
名称“我的四练计划”，周一至周日七行，每星期最多一个安排；点一天编辑动作。修改占用星期展示双方变化、确认交换，不提供训练日上移下移。
每次展示部位和动作概览，提供编辑、复制、调整顺序入口；区分“仅调整本周”和“修改长期模板”。

3. 训练进行中（最重要）
顶部为返回、训练名、经过时间和简短保存状态。当前动作“高位下拉”，旁边可直接看到上次记录“35 kg × 12 次 × 3 组”及日期。
每组以“组号 / 重量 kg / 次数 / 完成”紧凑排列，数字输入框足够大，可复制上一组、新增/删除组和填写可收起的动作备注。
其他动作紧凑切换；新增默认额外动作，替换保留已做组并只转移未达标目标。底部突出“查看总结”，稍后继续暂停并保留；固定休息条可展开、暂停/继续、延长和取消。
表现一组已完成、一组填写中、一组未完成；区分“仅本机保存”“待同步”“已同步”。返回不等于放弃。
这页优先追求少点击、易输入、上次数据容易找到，不使用大图挤占记录空间。

4. 历史记录
以日期和训练列表为主，可以切换紧凑日历。每条展示日期、训练名称、时长或补录标记、动作摘要，点击进入详情。
提供按动作看历史的入口。不要编造 AI 综合评分、恢复评分、卡路里或成绩排名。

5. 我的
展示简单个人资料、训练目标、每周目标、体重与体态记录入口，以及设置和退出登录。
提示私人资料和照片仅本人可见。不要加入会员销售、社交动态或不可用的 AI 按钮。

业务约束：
计划是模板，实际训练可以调整，修改模板不能改变历史。
确认保存生成一次实际训练记录。全部非空目标组在同一条记录达标才完成计划；部分训练和仅打卡可保存但不点亮安排，两条部分记录不合并。
示例数据只用于 UI 展示，不代表推荐训练方案。

交付要求：
先完成上述五屏，重点打磨训练进行中页，并保持连续的页面流程。
整理共用按钮、输入、训练列表项、分段切换、进度和状态提示，以及字体、颜色、间距规范。
如果当前工具支持，请提供可导出的页面截图、前端布局代码、样式、使用的资源和 DESIGN.md，便于之后适配已有 React 项目。
此阶段不需要真实后端、API 密钥、数据库或发布；前端框架信息不显示在产品界面中。
```

## 第二轮：补充计划编辑、完成记录和照片

```text
请保持当前“训练手记”项目已经确定的配色、字体、间距、组件和导航，继续补全以下页面，不重新设计另一套风格：

1. 计划编辑：名称、周一至周日概览、单日编辑，动作目标组数、时长动作可选每组目标秒数；改星期明确交换，动作可移到指定位置，整份统一保存，返回保留草稿及定位。
2. 动作选择：动作名称搜索、部位筛选、多选确认添加、“创建自己的动作”；以内置动作和私人动作列表为主，避免大型图片墙。
3. 训练总结：冻结用时并结束休息，日期、来源安排、实际动作和组、目标对照、感受与备注；部分可保存，允许校正用时，返回实时训练恢复累计计时并清除校正。
4. 历史详情/补录：查看或编辑实际动作、每组重量和次数及备注，清楚区别于计划目标；删除为低强调操作。
5. 体态记录与上传：按日期展示照片与正面/侧面/背面标签，填写日期、角度、可选体重和备注，显示仅本人可见，支持删除和上传失败重试。
6. 照片对比：两个日期、同一角度并排展示，照片裁切一致，可放大；显示日期和可选体重，无同角度照片时给出清晰提示。用中性占位图，不虚构前后变化效果或自动体态诊断。
7. 网页登录/注册：邮箱和密码，使用同一产品视觉；微信登录不作为当前网页注册的前提，后续小程序再适配。

补充关键状态：没有计划、首次训练、没有历史、没有照片、加载失败、输入校验、未保存离开提示、恢复草稿和待同步。
保持简体中文，手机优先、底部安全区域和单手操作。完成后检查从首页到训练、打卡、历史、照片对比的页面衔接。
```

## 定向修改：记录页不够好用时

```text
请只优化当前“训练进行中”页面，沿用现有设计系统。
把上次数据放到当前动作标题附近；让重量、次数和完成按钮在小屏上仍清晰且不横向滚动；复制上一组一键可用。
备注收起，其他动作紧凑显示。主按钮为查看总结，稍后继续暂停并保留，放弃训练另设低强调入口。
展示数字键盘弹出后的布局，确保当前组和保存状态可见。优先减少记录一组的点击次数，不增加装饰和大图。
```
