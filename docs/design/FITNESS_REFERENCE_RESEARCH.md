# 健身记录产品参考研究

核查日期：2026-10-04。用途：支持“训练手记”微信小程序的每周计划、训练记录和复盘设计。

## 阅读边界

以下四个对象均来自官方产品网站、官方帮助中心或项目维护方的仓库与文档。“已验证事实”是页面明确描述的功能；“设计推论”是结合本项目需求提出的选择，不能反过来当作参考产品已实现的功能。本次为文档核查，没有安装应用或进行实机交互测试；帮助文档可能与具体平台版本存在差异，尤其 Strong 的部分页面最后更新于 2021–2022 年。未克隆仓库、复制代码或提取品牌素材。

当前用户约束优先于参考产品：星期一至星期日安排每周训练；一次只编辑一天；长期固定计划与临时训练分离；逐组填写重量、次数、完成状态并休息计时；历史在进步停滞时仍可复盘；以轻量可视化激励持续记录。

## 1. Hevy：复用计划与现场记录

官方入口：[产品功能](https://www.hevyapp.com/features/)。

### 已验证事实

- Routine 是可重复使用的训练模板；可以设置动作、组数、重量、次数或次数范围、时长及动作休息时间。实际训练可修改这些数据并完成保存，也能从空白训练开始。完成一组会启动自动休息计时。[官方训练记录说明](https://www.hevyapp.com/features/track-workouts/)
- 训练中可显示上次表现；来源可选择该动作最近一次记录，或该动作在当前 Routine 下的记录。模板备注与单次训练备注也有不同作用范围。[官方训练记录说明](https://www.hevyapp.com/features/track-workouts/)
- 统计包括不同肌群的组数、训练次数、时长和容量等，并支持按周/月查看；月报可比较这些指标。[官方统计帮助](https://help.hevyapp.com/hc/en-us/articles/35702030346903-Hevy-Statistics-Explained-Track-Your-Training-Progress-and-Muscle-Growth)

### 可借鉴交互——设计推论

- 首页突出“开始今天的训练”，次级入口“临时训练”；两者进入同一记录页，但来源标签分别显示“来自星期一计划”和“临时训练”。
- 每个动作标题旁显示“上次：日期＋重量×次数”，点开后看各组；历史来源优先同计划日，找不到时明确说明使用最近一次动作记录。
- 完成组触发小型休息栏，支持增加时间、跳过、关闭；计时不遮挡下一组输入。
- 把计划备注视为长期提示，把本次备注视为历史内容，避免现场备注无意改动未来计划。

### 明确不照搬

不复制 Hevy 的品牌、页面样式、动作图片或商业产品源码。其官方功能列表覆盖社交动态、排行榜、教练等广泛功能；本项目首版不引入这些入口，也不把完整统计看板放到训练输入页。[Hevy 官方功能列表](https://www.hevyapp.com/features/)

## 2. Strong：让模板与一次训练的边界可见

官方入口：[Strong](https://www.strong.app/)、[官方帮助中心](https://help.strongapp.io/)。

### 已验证事实

- Template 不代表实际完成的训练：模板组不能勾选完成，没有完成时间/日期，编辑模板时不提供实际休息计时。[官方模板说明](https://help.strongapp.io/article/105-about-templates)
- 一次训练可从空白或模板开始；每组输入重量与次数后用复选框完成，训练结束后可以从 History 回看；不要求所有动作都完成才能结束训练。[官方训练流程](https://help.strongapp.io/article/229-my-first-workout)
- 官方休息计时说明描述了完成组后自动启动、手动启动、修改时长、跳过及按动作设置时长。该页面最后更新于 2021-02-08，本研究只借鉴行为，不将页面位置描述为现版保证。[官方休息计时](https://help.strongapp.io/article/231-rest-timer)
- 修改模板来源的训练后，官方帮助描述了更新模板、仅更新数值或保留原模板等结束提示。[官方模板更新说明](https://help.strongapp.io/article/177-update-template)
- 动作详情包含 History、Charts、Records 等视图，图表依动作类型而异；该帮助页标注 Charts 为 PRO 功能。[官方动作详情说明](https://help.strongapp.io/article/237-about-exercise-detail)

### 可借鉴交互——设计推论

- “编辑星期一计划”只编辑目标动作、组数与目标数据，不出现完成复选框或正在计时的状态；实际训练页明确显示“本次记录”。
- 在训练页临时替换动作、修改重量或增减组，只改变本次训练。完成后默认保存历史；“更新固定计划”另设明确操作，避免用户每次结束都处理多选对话框。
- 未完成组仍可结束训练，完成页分别列出“已完成”“未完成/未记录”；未填写不能计算成重量 0，也不能伪造成真实完成量。

### 明确不照搬

不照搬官方帮助中多种模板更新选项、会员限制、旧版计时页面位置。首版保留一条清晰路径：保存本次训练；需要长期改变时再去编辑相应的计划日。

## 3. wger：按训练日组织计划的开源参考

官方入口：[维护方公开仓库](https://github.com/wger-project/wger)、[官方文档](https://wger.readthedocs.io/en/stable/)、[官方实例](https://wger.de/)。

### 已验证事实

- 官方手册以一天作为 Routine 的基本单位：训练日包含动作，休息日可单独指定。`fit in week` 可让计划每周同一天重新开始，也支持非七天的自定义循环；手册说明其假设是连续数周重复训练。[官方用户手册](https://wger.readthedocs.io/en/stable/manual/routines.html)
- API 文档把计划拆为 Routine、Day、Slot、SlotEntry 等对象；真实历史另用 WorkoutSession、WorkoutLog。重量、次数、组数、休息等配置有各自对象，也支持按循环次数设置进阶规则。[官方 Routine API 文档](https://wger.readthedocs.io/en/stable/api/routines.html)
- README 列出训练计划、体重与测量、饮食、照片、REST API、自托管及基础健身房管理等功能。[维护方 README](https://github.com/wger-project/wger)
- 公开仓库 README 声明应用代码为 **AGPL-3.0-or-later**；`LICENSE.txt` 为 GNU Affero General Public License Version 3。README 将动作/食材数据许可单列为 Creative Commons，并要求看单条记录；文档许可单列为 CC-BY-SA-4.0。这里只记录声明，不判断本项目采用、修改或分发的法律后果。[README 许可部分](https://github.com/wger-project/wger#license)、[LICENSE.txt](https://github.com/wger-project/wger/blob/master/LICENSE.txt)

### 可借鉴交互——设计推论

- 计划首页固定显示星期一至星期日七行：训练日显示名称、动作数和“编辑”，休息日明确显示“休息”；七行是用户指定的产品结构，不声称 wger 提供同样界面。
- 点击一天进入单日编辑，页标题例如“编辑星期三”。返回七日概览时将修改保留在整份计划的编辑草稿中，最后统一点“保存计划”；不要求用户在一张长表内编辑整周，也不将返回误当作已持久化保存。
- 数据关系借鉴“计划日”和“实际训练”分离的思路：开始时生成一次训练快照；历史保留当时动作与组数据，修改未来计划不改变过去记录。
- 首版只提供固定星期模式。参考产品的任意循环和进阶规则证明可扩展空间，但本项目不因此增加模式开关。

### 明确不照搬

不克隆或复制 wger 代码、完整对象层级、动作数据和图片。首版不照搬其自定义周期、自动进阶规则、饮食和健身房管理。特别是手册明确强调重复计划的使用假设；本项目临时训练需求要由独立入口满足，不强塞进固定计划。[官方用户手册](https://wger.readthedocs.io/en/stable/manual/routines.html)

## 4. FitNotes：停滞期仍有意义的动作复盘

官方入口：[FitNotes](https://www.fitnotesapp.com/)、[官方帮助](https://www.fitnotesapp.com/help_overview/)。

### 已验证事实

- Routines 用于保存并记录经常重复的训练，以减少每次临时录入或复制历史的操作。[官方 Routine 说明](https://www.fitnotesapp.com/routines/)
- 动作历史能看各次训练的组和备注；图表包含最高重量、总次数、训练容量、指定次数对应重量等指标。点选图点可查看具体数据并进入那次训练；支持趋势线以及从 0 开始的纵轴选项。[官方进度追踪说明](https://www.fitnotesapp.com/progress_tracking/)
- Calendar 有月历和列表两种视图，可按肌群或动作筛选，也可进入当天完整训练。[官方 Calendar 说明](https://www.fitnotesapp.com/calendar/)

### 可借鉴交互——设计推论

- 历史主入口保留易扫读的日期列表，月历作为次级切换；动作详情将最近记录列表与一张趋势图放在一起。
- 默认以“最高重量”或“同重量次数”理解变化，另提供“已完成组数”和“记录容量”。例如重量连续四次未变，但同重量次数从 8 次增加到 10 次，复盘仍有可读信息；这是设计示例，不是用户成绩或训练建议。
- 图点必须能回到原始组和备注，方便解释减量、临时替换或休息变化；不通过单一上升曲线给用户下“训练失败”结论。
- 少量数据先展示最近三次记录；足够数据后再画趋势。坐标轴写单位和范围，缺失数据留空，避免 0 值和夸张缩放制造进步或退步。

### 明确不照搬

不一次暴露官方列出的所有图表、筛选条件和估算指标。首版不以估算 1RM、综合评分或自动训练诊断做激励；先让真实记录、次数与组数变化可追溯。[FitNotes 官方进度追踪说明](https://www.fitnotesapp.com/progress_tracking/)

## 本项目建议：将参考收敛为六项可执行决定

以下均是设计推论与用户约束，不是竞品功能声明。

1. **计划按星期组织、按天编辑。** 七日概览负责看整周，单日页负责动作、组与目标修改；休息日有明确状态。
2. **固定计划、临时训练和历史分离。** 从计划启动保留来源与快照；临时训练没有计划日来源；现场改动默认只影响本次；历史改动另走历史编辑入口。
3. **训练页围绕一个组的记录优化。** 组号、重量 kg、次数、完成同一行；上次数据近旁可见；备注收起；加组、复制上一组和替换动作可直接操作。
4. **完成组之后自动休息。** 休息栏持续可见且不挡输入，可跳过和调时长；中断恢复按目标结束时间计算剩余时长。后者是实现建议，本研究未查证微信后台计时能力，不承诺后台通知效果。
5. **记录页承担复盘。** 日期历史与按动作趋势互通；看同动作、重量、次数、完成组及备注。容量仅为已填写且完成的适用动作组之 `重量×次数` 汇总，作为记录指标，不能直接称为训练效果；跨动作、器械或单边重量口径不混算。
6. **激励来自可解释的事实。** 首页显示“本周计划已打卡 2 / 4 天”和进度，实际训练次数另列；完成页显示真实记录与一个轻量完成反馈；趋势持平也展示持续记录和本次与上次的组差异。计划训练完成按不同计划日计数，重复训练和临时训练另外计实际次数，避免临时训练自动顶替固定日。只打卡与有组记录的训练必须在统计中可区分。

## 未验证项与后续验证

- 未找到支持“参考对象都按星期一至日七行、一次编辑一天”的证据。这两点来自当前用户需求，不能用竞品截图替代。
- 未核实 Hevy、Strong、FitNotes 的完整当前平台差异、订阅价格与免费配额，因这些不是当前设计决定所需的信息；文档中出现的平台和付费标记只按来源注明。
- 微信小程序恢复草稿、后台计时、键盘、安全区及休息提醒应在原型和实机中验证。当前研究支持交互方向，不证明这些运行条件已经满足。
- 所有界面、文案和素材应由本项目独立设计；公开源码许可证的核查仅是事实记录，本研究不提出法律结论。
