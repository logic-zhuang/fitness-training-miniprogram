# 训练手记：每日训练、照片日志与微信登录

日期：2026-10-07。状态：正在实施。v3 业务、训练推进、显式提交、本机/云端状态分离、微信登录接口和小程序照片日志已进入代码。新增本周覆盖恢复、准备动作时暂停计时、独立我的动作入口、上传生命周期修复和重新登录/绑定重试。当前证据与完整剩余工作见 [v3 实施与验收](../FITNESS_V3_ACCEPTANCE.md)。

最新自动检查 85 项通过、1 项真实接口检查未启用而跳过；TypeScript 与网页生产构建通过，小程序本轮修改后的 WXML/WXSS 已重新经官方编译器检查。七天日期交换改为选择、预览双方变化、明确确认；动作菜单分组，移动先预览顺序再确认，休息与底部操作共用容器。自由训练组数/秒数与未确认组提交规则已在网页和小程序对齐。网页日期交换、总结、照片及自由训练提交有独立浏览器操作证据，提交、总结与日志 320/430px 无横向溢出。网页训练调整入口、个人库管理与更多菜单仍需对齐，实际微信身份、手机布局和完整体验未验收。当前小程序开发地址仍为 127.0.0.1:8001，手机需要实际可达后端与服务端微信凭证。

本方案替代上一轮“动作完成不自动推进”“先总结再保存”的交互提案。既有目标快照、部分保存、幂等、账号隔离等数据规则继续适用。代码现状及提交无变化问题的证据边界见 [上一轮检查](FITNESS_WORKFLOW_REDESIGN.md)。

## 1. 产品主线与导航

主线：默认沿用每周计划 → 开始今天的训练 → 逐动作记录 → 每个动作完成回顾并自动进入下一个 → 提交本次训练 → 总结及可视化 → 可选添加照片 → 日后从训练日志回看。

底部一级导航精简为“今天 / 计划 / 我的”。训练日志和统计从“我的”进入；首页保留最近一次记录快捷入口。进行中的训练、动作完成页、总结和照片详情使用子页面，隐藏底部一级导航，避免误离开。

统一术语：周计划是一周的重复模板；周一等各有一个安排，每个安排可含多个动作；一条训练记录包含这次实际完成的多个动作和组。动作完成不单独生成一条训练历史。

## 2. 默认计划与临时调整

设置一次周计划后按星期自动显示，不每天弹计划确认或进入编辑页。首页主要按钮只有“开始今日训练”；有草稿优先显示“继续训练”。休息日或没有计划也允许“自由训练”，不要求先建计划。

“调整今天”是首页次要文字入口，包含：调整动作、改练本周另一安排、换到其他日期。常规操作默认仅影响本次或本周，不修改长期模板。

- 今日动作调整：从我的/内置/最近选择器添加或替换、调整顺序与组数；下周恢复周计划。
- 本周调日：按具体日期保存覆盖，例如本周三与周五交换；目标日期有安排时展示双方并确认。下周恢复模板。日历要显示“本周已调整”，提供恢复入口。
- 小程序在同一弹层选择原日期与目标日期，七天均可选择；预览两天各自从什么安排变成什么安排。取消不写入，明确确认后保存；失败保留选择，重试不反向交换。不使用最多 6 项的原生操作菜单承载七天。
- 长期修改：仅在“计划 → 编辑周计划”中完成。按钮明确“保存每周计划”。
- 已开始的训练沿用开始时的快照；更改日期或模板不能重写正在进行或已完成的记录。已有完成记录的日期不允许靠交换重分配成绩。
- 休息日自由训练可以保存实际记录，不自动完成其他计划日。

技术上增加按日期存储的本周覆盖，保留来源计划日身份；不能直接交换模板的星期来冒充“只改这周”。所有新增字段须版本化、兼容旧缓存及阻止旧客户端覆盖，具体版本在实施时确定。

## 3. 按动作推进

训练页以当前动作为中心。上方固定“动作 2/4”和可展开的全部动作清单，支持任意跳转；主体只显示当前动作的组记录。底部布局统一，不将替换、删除、移动等操作铺满页面。

每组需有效实际数值并明确确认完成。已有数据只作参考，不自动计完成。当前动作全部目标达标时进入该动作的完成页，显示动作名称、实际组数、本次重量/次数或秒数、下一动作。

动作完成页默认停留约 2 秒后自动进入下一个未完成动作，并有“立即继续”和“留在此页”入口；查看详情、编辑或用户取消推进时停止倒计时。保留已启动的组间休息，不重复启动。下一动作进入后也不自动记组、不自动启动时长组计时。

实现约束：自动推进只由本次用户确认导致的“未完成 → 完成”事件触发一次；重开、刷新、切后台回来、浏览历史不重复推进。后台时暂停页面跳转，回前台给用户明确继续入口，防止恢复时连续跳多页。总训练计时仍沿用既有后台规则。

时长实际不足目标，例如 20/30 秒，保留实际组，但不显示目标完成页。提供“继续记录”或“调整本次目标”；明确调整后才能按新目标判断。

自由训练或额外动作没有原计划目标时，使用本次安排的组数判断动作记录是否结束，用户也可在菜单明确“完成这个动作”；不能因此自动点亮某个周计划日。

自由训练可调整本次组数；已确认组必须保留，不允许缩减到已确认组数以下。时长动作可设置每组秒数，未达到仍保留实际记录，但不会自动推进。动作菜单按“这个动作 / 本次训练”分组；移动使用位置选择与顺序预览，确认后仍停留同一动作，已有组不受影响。菜单在后台、账号变化或用户切换动作后关闭，过期操作不能修改另一个动作。

最后一个动作完成后进入“全部动作已完成”页，显示“4/4 个动作，12/12 个目标组”；停止自动跳转，主按钮为“提交今日训练”。若还有额外动作待练，提供继续入口，不能自动提交。

## 4. 提交、总结与提前结束

完整路径为：最后动作完成页 → 用户点击提交 → 持久保存成功 → 总结页。取消此前每次都必须先看总结再确认保存的双重提交流程。

最后动作完成页冻结用时并结束休息，等待提交和照片不计入训练时间。返回继续则恢复累计计时。自由训练主按钮叫“保存本次训练”；提前结束的菜单操作叫“结束并保存部分训练”。

提前结束不被隐藏或禁止：显示具体缺项和已填未确认组，允许返回或只保存已确认实际记录。未完成计划显示部分完成，不伪装完成。无实际完成组时可保留草稿或明确仅打卡。

提交中立即显示状态并防重复点击；失败保留结束页和重试入口，沿用同一记录身份。成功必须展示可理解的保存位置与内容，点击记录能看到同一条数据。

未确认组检查也覆盖最后动作自动进入待提交的路径。提示具体动作和组，取消仍在待提交页；确认后原始未确认数据保留，但不计入统计。小程序已经确认且内容未变化时不重复提示；返回继续记录或修改输入后需重新检查。待提交默认收起动作明细，只展示日期、用时、组数、完成情况、可选用时校正和主要提交按钮。

总结页面顺序：

1. “本次训练已保存”及保存/同步状态；计划另显示达标或部分完成。
2. 日期、训练部位标签、训练用时、实际动作数与组数。
3. 本次目标完成进度；各动作的实际组数分布，时长动作仍按实际组数计组，不把秒数和重量放同一轴。
4. 可展开的动作明细。单动作历史趋势作为次级内容，有历史才展示，不生成训练质量评分。
5. “添加今日照片（可选）”：相册或拍照；感受和备注同为可选。
6. 底部“完成，返回首页”；查看日志为次要入口。

训练保存和照片上传是两个独立结果。照片失败不能回滚已保存的训练。未登录时只能明确显示本机保存；账号照片同步需要登录。

## 5. 照片入口与按日期归档

当前实现：小程序已有相册/拍照、持久队列和日期日志入口；后端已支持照片用途、可选角度、训练关联、部位标签和元数据编辑。网页已改为普通健身日期日志，新增 IndexedDB 待上传队列和元数据编辑；本机图片保存、刷新关联、旧库迁移与账号复合身份有实际浏览器证据，真实账号上传和微信环境联调仍需完成。

两个主要上传入口：训练总结中的“添加今日照片”；“我的 → 训练日志 → 某日/某次详情 → 添加照片”。休息日也可从日志记录照片，不创建虚假的训练完成记录。

- 默认归入本次训练的真实日期，而不是上传日期；以后补传仍归原日期，可手动确认改归日期。
- 照片可以关联具体训练 ID；同一天两次训练分别保留，日期页聚合展示，不能覆盖。
- 日期旁显示“胸 · 三头”等标签，默认来自当日实际完成动作的部位，并允许备注修正；不把未练到的计划部位当作事实。
- 健身照片不强制正面/侧面/背面；这些作为体态记录的可选标记。既有体态照片保留原信息，不强制绑定训练。
- 每张照片有选择中、待上传、上传中、已上传或失败状态；逐张重试不重复创建。离线选择如需跨重启保留，必须落到账号隔离的持久文件存储，不能只保留微信临时路径。
- 私人照片沿用鉴权和本人访问；删除单张照片不删除训练，删除训练时明确保留照片为按日期归档并解除关联，不隐式级联丢图。

后端已扩展照片的用途、可选角度、可选训练关联与部位/备注信息并校验训练归属，仍需真实上传及微信环境联调。仍复用现有私有照片接口及文件校验，API 变更生成客户端。普通上传不得修改原训练目标快照。

## 6. 训练日志怎么排版

“我的”第一组入口为“训练日志”“我的动作”，设置和备份下沉；日志包含训练记录和照片，不另做一套容易混淆的相册数据。

日志默认按月份分组、日期倒序，顶部可切“全部 / 有照片”。首版不增加独立日历视图。

日期行：`10 月 5 日 周一    胸 · 三头`。下面展示用时、动作数和实际组数；有照片时显示整齐的缩略图，无照片时不占空白图片区。

缩略图统一裁剪比例：一张为 4:3 横图；两张为双列方图；三张及以上为三列方图，列表最多预览三张，最后一张叠加“+N”。点开原比例大图，避免列表瀑布流造成日期和记录对应不清。

同日多个训练按小标题分段，并标明照片关联的训练。当天无训练的照片显示自填标签或“日常记录”；不产生训练次数。

日期详情：日期和部位 → 训练摘要 → 照片区 → 动作记录折叠列表 → 备注。页头“更多”里放修改记录、改标签与删除，浏览时不显示输入框。修改保存更新原记录，不增加训练次数。

## 7. 全局排版规范

固定白底、深色文字、绿色主色。每页只设一个明显主按钮，主操作在固定底部区域；次操作用文字，低频和破坏操作收进更多菜单。

移动端建议基准：左右 16px 留白、区块间 24px、组行间 12px；标题 22px、正文/输入 16px、辅助信息 13px；触控区域至少约 44px。这些是设计基准，需在 320–430px 上验证换行和键盘遮挡。

今天：日期及一周小格 → 今日训练摘要 → 动作预览 → 主按钮。计划：七天简洁列表 → 单日编辑。训练：动作进度 → 当前动作和组 → 休息条 → 操作区。完成页：一个完成标识、实际数据、下一动作。总结：结果 → 可视化 → 照片。

不在每段后堆一排绿色按钮；统计数字同一行、长文案收起、动作名允许换行。训练页休息条和底部主操作由同一布局管理；键盘出现时保证输入和“完成输入”可见，不叠三层固定工具栏。

## 8. 小程序改为微信登录

当前“我的”已提供微信登录、同身份过期重登和已有网站账号绑定入口；小程序调用 `wx.login`，服务端实现 code 换身份与项目令牌签发。服务端凭证与真实微信身份尚未联通验证，不能把接口实现或模拟身份测试当成真实微信登录完成。

产品方案：未登录展示“微信登录，同步训练记录”，无需填写服务器地址和邮箱密码；允许先本机记录。登录后保持登录状态，正常使用不反复打断。昵称头像为可选个人资料，不把手机号或头像获取当作记录训练的前提。

技术方案：小程序取得临时 code → FastAPI 服务端向微信换取身份 → 映射到现有内部用户 → 签发项目登录令牌。AppSecret 仅存服务端；客户端提交的 openid 不作为身份凭证。沿用 FastAPI 和 PostgreSQL，不需要改成微信云开发。

既有网站账号通过单独“绑定已有账号”流程证明账号归属后绑定，不能根据昵称自动合并。未登录本机记录导入账号需列明数量并确认，幂等合并不覆盖已有云端记录。

实施参考：[微信官方示例仓库](https://github.com/wechat-miniprogram/miniprogram-demo)、[微信登录文档入口](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[code2Session 文档入口](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)。本轮官方文档网页读取失败，登录技术细节在实施时通过官方可用文档与开发者工具再次核验；此处是拟采用流程，不表示已经联调。照片组件可参考 [腾讯 TDesign 小程序上传实现](https://github.com/Tencent/tdesign-miniprogram/blob/develop/packages/components/upload/upload.ts)。

## 9. 实施顺序

1. 先完成包含今天、当前动作、动作完成、全部完成、总结、日志的交互原型，检查自动推进和按钮位置。
2. 实现默认计划与临时调整、逐动作推进、一次提交和明确保存结果；先复现并修复现有提交无变化问题。原型按钮可点击不等于真实保存已成功。
3. 接通微信登录与已有账号绑定，保留本机训练及账号隔离；服务器地址放开发配置。需要用户后续在本机服务端配置 AppSecret，不在聊天中发送。
4. 接通照片上传、按日期与训练关联、总结入口、我的训练日志；验证断网、重启及补传。
5. 统一视觉并完成开发者工具、真机全流程验收。自动处理器测试只能验证局部逻辑，不能替代真实页面点击。

验收主线：无需每日确认计划即可开始 → 三动作依次完成、完成页自动推进 → 最后动作完成不自动提交 → 提交后看到真实保存结果与图表 → 照片上传 → 从我的按日期和部位找到照片、打开同一训练记录。另测部分训练、时长不足、临时换日、后台恢复、重复点击、离线上传及账号切换。

本方案正在落实到业务代码；具体已实现内容、实际检查与剩余条件以 [v3 实施与验收](../FITNESS_V3_ACCEPTANCE.md) 为准。原始旧方案保留供追溯，不代表当前实现状态。
