# 私人体态照片

登录账号的体态档案已接入真实后端。体验页照片仍在本机。支持拍摄日期、正面/侧面/背面、备注、分页、相同角度不同日期对比、删除和失败重试。

## 数据与权限

- `POST /api/v1/fitness/photos`：multipart，`photo_id`、`date`、`angle`、`note`、`file`。
- `GET /api/v1/fitness/photos?offset=0&limit=24`：只返回本人照片元数据，每页最多 100 张。
- `GET /api/v1/fitness/photos/{photo_id}/content`：携带登录令牌读取本人 WebP，浏览器通过生成客户端取得 Blob；接口没有公开图片链接。
- `DELETE /api/v1/fitness/photos/{photo_id}`：只删除本人的文件与元数据。

账号归属来自服务端登录身份，包含管理员在内的其他账号不能读取或删除；同 ID 在不同账号下分别存储。内容响应使用 `private, no-store`；退出后移除查询缓存并释放页面对象 URL。

迁移 `b6317a49d205` 接在 `a5f19d42c803` 后面，只新增 `fitnessphoto` 表及按账号/日期的索引。图片内容与元数据在 PostgreSQL 同一事务中保存；账号删除时级联删除照片。现阶段适用于本人和少量朋友，后续用户/照片量增长时再迁移至私有对象存储；备份数据库时需包括此表。

## 图片处理

接受静态 JPG、PNG、WebP，文件最大 10 MiB、像素数最大 5000 万。后端校验实际可解码的图片内容，按 EXIF 转正，最长边缩至 2048 像素，透明区域填白，以 WebP 保存并去除原图 EXIF/GPS。保存内容适合对比展示，不是原图归档，用户需自己保留原图。动画、无效文件和超限图片被拒绝。

## 重试与旧照片

上传 ID 在同一表单重试中保持不变；服务端依据 ID 与完整请求指纹返回已保存的回执，避免网络中断后重复创建。相同 ID 配不同内容返回 409。上传失败不清空文件、日期及备注；当前页面可重试，刷新后需重新选文件。删除失败保持确认框和照片，404 重试视为已删除。

旧 IndexedDB 账号照片按 `user:<用户 ID>` 查询，仅本人登录后看到迁移入口。用户点击同步后，逐张上传，确认成功才删除该张本机副本；失败或本机删除失败时停止，余下副本保留，下一次从剩余照片继续。体验照片不自动传入个人账号。

## 验证

后端覆盖本人读取、未登录/其他账号/管理员隔离、并发重复上传、内容冲突、无效文件和日期、大小与备注限制、方向纠正及 EXIF 清理、分页、删除和账号级联。前端测试覆盖同步中断后的剩余照片及相同请求恢复、本机删除失败停止迁移。
