### 关于要不要上云开发（CloudBase）

现在是「原生小程序 + 自建 FastAPI 后端」，后端已经跑通，账号、训练、照片都在自己库里。**不建议整体迁移**——改动面太大，收益主要是省服务器运维。

如果只是想解决 P0 里的服务器和 HTTPS 麻烦，有一个折中办法：**只把照片存储换成云存储**，小程序端直接用 `wx.cloud.uploadFile` 直传，可以少配一个 uploadFile 合法域名、也减轻自己服务器的带宽压力。训练记录这类结构化数据继续走现有接口。

（注意：真要用云开发，需要在微信开发者工具里点「云开发」按钮开通环境，且必须是正式注册的小程序账号——测试号的云开发按钮是灰的。）

## 补充与修正（2026-10-14 代码核对后）

> 以下三条是对上文的修正/补充，核对时实际改动已同步落地。

1. **config.js 的忽略方式修正**：原清单建议「加进 .gitignore」，但 config.js 已被 git 跟踪，对已跟踪文件加 gitignore 不生效。正确做法（已执行）：git rm --cached miniprogram/config.js 取消跟踪 → 新增 miniprogram/config.example.js 模板入库 → .gitignore 加入 miniprogram/config.js。本地 config.js 保留当前 IP 不入库。

2. **补当前联调阻塞（优先级高于 P1）**：
   - **校园网客户端隔离**：CUP-WLAN 默认开启 AP 隔离，同一 Wi-Fi 下手机与电脑互 ping 不通，这是微信真机登录一直失败的根因，不是配置问题。绕过办法：手机开个人热点，电脑连手机热点（192.168.x.x 网段天然互通），再把 config.js 改成热点分配的新 IP。
   - **后端进程无守护**：uvicorn 是手动启动的，电脑休眠/重启后即停止。联调前需重新启动（ackend 目录 .venv 的 uvicorn app.main:app --host 0.0.0.0 --port 8001）；正式环境需常驻进程/服务托管。

3. **P1-9（401 静默续期）降级**：自用小程序 token 过期后手动点「重新验证登录」可接受，不必优先做，可挪到 P2。
